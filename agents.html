The seven heads

Every agent, explained properly

Each one is a markdown definition file — mission, mindset, decision frameworks, output contracts. Here's the human translation.

Hunter

mode: primary · temperature 0.2 · the exploitation lead

What it does: runs the full reconnaissance-to-exploitation pipeline — subdomain enumeration, CDN filtering (so scans hit real servers instead of Cloudflare), port discovery, vulnerability templates, and directory fuzzing. Then it probes everything it found in continuous cycles.

Why it's built this way: most hunters don't fail at exploitation, they fail at asset discovery. So Hunter treats recon as 80% of the job and carries a decision table for every situation — a 403 means "bypass me", a WAF block means "switch to the vendor-specific bypass table", silence after N cycles means "change layers entirely".

You'll see it
  • Run chaos/httpx/naabu/nuclei/ffuf pipelines
  • Save every lead instantly with a hash
  • Refuse to proceed without confirmed scope
Built-in discipline
  • Never exploits past minimal proof on big finds
  • Tags everything UNVERIFIED for Verifier
  • Logs what worked/failed to memory

Verifier

mode: primary · temperature 0.1 · the quality gate

What it does: takes every finding and tries its hardest to destroy it. Baseline request vs exploit request, three replay attempts, response diffing, false-positive signature checks — then an honest CVSS score and a confidence percentage.

Why it exists: bounty platforms track researcher accuracy. Three sloppy reports can end an account. The Verifier's charter is simple: "if you can't reproduce it confidently, reject it" — because a real bug can be re-found, but a reputation can't.

Confidence scale
  • ≥80% → VERIFIED, moves forward
  • 50–79% → PARTIAL, flagged for human review
  • <50% → REJECTED with written reason
Rejection reasons teach
  • Every rejection notes the FP signature
  • Patterns flow back to Hunter's memory
  • Dry spells raise standards, not lower them

Reporter

mode: primary · temperature 0.1 · the submission writer

What it does: converts verified findings into platform-ready reports — title under 120 characters, summary that states severity unambiguously, working curl PoCs with truncated proof output, CWE mapping, CVSS vector, and impact phrased in the business's own terms.

The thinking behind it: a triager reads your report between meetings, comparing it against forty others. The best report makes their job a five-minute confirmation. So Reporter is trained on report psychology: show don't claim, honest severities beat inflated ones, duplicates lose — report fast but never skip verification for speed.

Plan

mode: primary · temperature 0.3 · the strategist

What it does: before anyone fires a packet, Plan researches the target on the open web — tech stack, program scope, known CVEs, acquisitions — then produces a prioritized attack plan: P0 authentication flows first, P3 header trivia last, with success criteria and pivot conditions ("no findings after N cycles → switch approach") defined up front.

Auditor

mode: primary · temperature 0.1 · the code reviewer

What it does: when you have source code instead of a URL, Auditor reads it like an attacker — maps trust boundaries first, sweeps dangerous sinks second, then goes deep where it matters: authorization logic, session handling, crypto misuse, mass assignment. Every finding must show file, line, reachable path, and a minimal proof — "dangerous function exists" with no route to it doesn't count.

Recon

mode: subagent · temperature 0.1 · the surface mapper

What it does: the fast path. Exhausts free passive sources (certificate transparency, archives, passive DNS) before touching the target, resolves and deduplicates, tags CDN-shielded hosts so nobody wastes time scanning them, harvests JS bundles and source-map leads, and stops when two consecutive phases add less than 5% new assets.

Its contract: every result carries evidence of origin, high-value targets ranked by attack value, and an explicit "safe to port scan / do not port scan" split.

Debug

mode: primary · temperature 0.4 · the self-improvement engine

What it does: sees across all agents. When something breaks downstream (bad reports ← weak verification ← sloppy hunting), Debug diagnoses upstream. Every logged mistake must end with a concrete prevention rule — memory entries without prevention rules are just diaries.

The soft part it handles: frustration. When things go wrong, Debug de-escalates, fixes immediately, documents, prevents. It also runs the Self-Rescue Protocol culture: search the web in parallel, fetch primary sources, cross-verify, never guess.
